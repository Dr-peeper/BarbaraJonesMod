# The Barbara Jones Mod

A Minecraft **Forge 1.20.1** mod. Barbara Jones, Cayden Cobb, the Krave Monster,
and a questline that runs from a bowl of cereal to revenge on The Plug.

**Rule #1: do not let Cayden Cobb die.** He is a tamed companion, and when he
dies near you the Krave Apocalypse fires — ten escalating death stages, and from
the eleventh death onward it simply never stops.

---

## Getting started

```bash
git clone https://github.com/Dr-peeper/BarbaraJonesMod.git
cd BarbaraJonesMod
```

**New here? Read [HANDOFF.md](HANDOFF.md) first.** It covers the architecture,
the build traps that have already burned us, and the bugs still open.

### Building

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1
```

The finished mod lands in `build/libs/`. Drop it in your `mods` folder.

Two things the build script exists to protect you from:

1. **`-ExecutionPolicy Bypass` is not optional.** Without it PowerShell blocks
   the script — and the shell wrapper still returns exit code 0, so a build that
   never ran looks like a build that succeeded.
2. **The jar must be reobfuscated.** We compile against Mojang names; Forge runs
   on SRG names. If Gradle's `reobfJar` step fails, `build/libs/` keeps a
   correctly-*named* jar full of the wrong names, which loads far enough to look
   fine and then dies with `NoSuchMethodError`. `build.ps1` now counts SRG
   references in the finished jar and refuses to report success if they are
   missing. **Don't remove that check.**

### What you need locally

`.tools/` (a JDK 17 and Gradle 8.1.1) is gitignored — roughly 740 MB, too big
for the repo. `build.ps1` looks for them at `.tools\jdk17\` and
`.tools\gradle\gradle-8.1.1\`. Copy them from another checkout or install your
own.

## Working on this at the same time

Two people editing one branch will trip over each other. The habit that avoids
almost all of it:

**Always rebase before you push.**

```bash
git pull --rebase        # replay your commits on top of theirs
git push
```

If you push straight to `main` without pulling first, git rejects it and you end
up untangling a merge you didn't need.

**For anything more than a small edit, branch:**

```bash
git checkout -b krave-tools-rebalance
# ...work, commit...
git push -u origin krave-tools-rebalance
```

Then open a pull request. This matters most because a lot of this mod lives in a
handful of very large files — `KraveApocalypse.java`, `ApocalypseClient.java`,
`CaydenCobb.java`. Two people in the same file on the same branch is where the
painful conflicts come from.

**Rough split that keeps you out of each other's way:**

| Area | Files |
|---|---|
| Entities & AI | `entity/` |
| The death cinematic | `apocalypse/`, `client/ApocalypseClient.java` |
| Items & recipes | `item/`, `content/ModItems.java`, `data/.../recipes/` |
| UI & books | `client/*Screen.java`, `client/CaydenHudClient.java` |
| Art & audio | `tools/*.ps1`, `resources/assets/` |

Assets are generated by the PowerShell scripts in `tools/`, not hand-drawn.
Change the script and re-run it rather than editing the PNG, or the next person
to run it will overwrite your work.

## What's in it

- **21 items**, **11 entity types**, **61 recipes**, **39 sound files**
- Barbara Jones — calm until her stash runs out, you taunt her with grass, or
  she catches you getting high
- Cayden Cobb — a companion who needs feeding and Terraria-style housing
- The Krave Monster — a boss that teleports constantly and trails afterimages
- The Plug — sells grass for emeralds, shorts you one time in four
- Krave tools — better than diamond, each with a deliberately infuriating catch
- **The Krave Manual** — an in-game book explaining all of it, handed to you on
  your first join
