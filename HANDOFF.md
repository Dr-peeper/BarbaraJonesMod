## What this is

A Minecraft **Forge 1.20.1** mod built as an inside joke between the user and a
friend. It is *not* being shipped publicly. It dramatises a set of YouTube
videos about a woman named Barbara Jones and a kid named Cayden Cobb.

**Consent note, stated by the user and carried forward:** the photo-derived
textures are of the user's friend, who gave explicit permission. Quote: *"the
photos of the real person are my friend and he gives full permission. this is
just a funny joke we are doing we aren't shipping this to anyone."*

**Content lines already drawn and not to be crossed.** Earlier in the source
videos there is material I declined to implement, and the user did not push
back: an adult character's sexual advances toward the kid, a gun-to-the-head
threat, and any belt-beating/spanking mechanic (Mom's Belt exists as an inert
memorabilia item only). The videos' background music is also excluded for
copyright; only dialogue audio was used. Keep these exclusions.

## Building — read this before you build

```bash
# from the repo root
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1
```

(On the user's machine the checkout sits in a folder named `BarbaraJonesMod1201` under `C:/Users/ADMIN/`.)

Three hard-won rules:

1. **`-ExecutionPolicy Bypass` is mandatory.** Without it the script is blocked,
   and the wrapper *still reports exit code 0*, so a "successful" build may
   never have run at all. Always grep the output for `BUILD SUCCESSFUL`.
2. **Never ship a jar without confirming it is reobfuscated.** The code is
   compiled against Mojang names (`nutrition(int)`); Forge runs on SRG names
   (`m_38760_`). Gradle's `reobfJar` rewrites them. When that task failed once,
   `build/libs/` kept a correctly-*named* jar with Mojang-named contents, which
   loads far enough to look fine and then dies at mod construction with
   `NoSuchMethodError`. This reached the user. `build.ps1` now counts SRG refs
   in the finished jar, restores from `build/reobfJar/output.jar` if they
   diverge, and throws rather than reporting success. A healthy jar shows
   ~940 SRG references. **Do not weaken that gate.**
3. Build takes ~15–40 s (the Minecraft decompile is cached).

## Architecture

Standard Forge 1.20.1: `DeferredRegister`/`RegistryObject`, `SynchedEntityData`,
`Goal`-based AI, JSON models + recipes, `DistExecutor` guarding all client-only
code. Java 17, official Mojang mappings.

- `BarbaraJonesMod.java` — entrypoint; registers `ModItems`, `ModSounds`,
  `ModEntities`, `ModTabs`, and `ModNetwork` in `commonSetup`.
- `EventHandler.java` — login grants (manual, quest book, cookbook, housing
  query) and the first Cayden spawn; the server tick that drives the
  apocalypse; `LivingDeathEvent` → apocalypse trigger; death-stage counter.
- `content/ModEntityAttributes.java` — **all 7 living entities must be
  registered here** via `EntityAttributeCreationEvent`. Missing entries caused
  "Invalid player data" on login. Every melee mob also needs
  `ATTACK_KNOCKBACK`, or `MeleeAttackGoal` crashes the integrated server the
  instant that mob swings.
- `apocalypse/KraveApocalypse.java` — the whole staged cinematic, server-driven.
- `client/ApocalypseClient.java` — client rendering for it.
- `net/` — `ModNetwork` (SimpleChannel), `PacketApocalypse` (id 0),
  `PacketCaydenStatus` (id 1).
- `housing/HousingValidator.java` — Terraria-style room validation.

**Content scale:** 52 Java files, 21 items, 11 entity types, 61 recipes,
39 sound files.

### Entities
`barbara_jones`, `cayden_cobb`, `krave_monster`, `nugget`, `daniel`,
`mom_cobb`, `the_plug`, plus effect entities `krave_meteor`,
`giant_krave_box`, `krave_tornado`, `sky_cinematic`.

Two class-hierarchy constraints that are not obvious:
- `Nugget extends Cat` — forced, because `CatModel<T extends Cat>`.
- `CaydenCobb extends TamableAnimal` from **`net.minecraft.world.entity`**, not
  `...entity.animal`. Getting that import wrong cascades into ~90 errors.
- `Blocks.GRASS` is correct for 1.20.1. `Blocks.SHORT_GRASS` is 1.20.3+.

## Game design — the parts that matter

**Rule #1 of the mod: do not let Cayden Cobb die.** When a tamed Cayden or a pet
Barbara dies near their owner, the Krave Apocalypse fires: 10 escalating death
stages (each tied to one of the 10 uncanny faces in `faces.webp` and to a canon
event from the videos), culminating at stage 10 with the Krave Monster climbing
out of the crater. **Death 11+ is endless mode with no in-game cure** — I raised
this with the user and offered a config toggle or a craftable "Krave Cleanse";
**they never answered. Still open.**

The player takes no damage during any of it.

- **Cayden**: auto-tames to the nearest player. Feeding Krave gives +1 attack
  per 5 boxes but makes him fatter and slower; 25 unlocks Krave Rage. Needs
  real housing (6 conditions) or he won't move in. Attacks every hostile on
  sight and they all target him back.
- **Barbara**: goes psycho when her stash empties, when taunted with grass, or
  when she catches you getting high.
- **The Plug**: sells grass for emeralds (shorts you 1 in 4), scams you with
  Mom's $500, and snipes Cayden unprovoked from 40 blocks.
- **Krave tools**: 5 tools, better than diamond, each with a deliberately
  infuriating drawback.

## Recently completed

- **Duhl Wol NPC**: arrives daily in a car, demands escalating tribute (dirt → stone → andesite → iron → emerald → $4 dollars). 40 HP (4× zombie), 3 damage (1.5×), pin stun ~2s. 5-minute timer to deliver or he turns hostile. Once paid, leaves 1–2 days. Daily spawn wired into `EventHandler` per-player tracking. Placeholder humanoid + car renderers. Compiles cleanly, not yet built/tested in-game, horror audio/visuals queued.
- **Ambient horror ("Dread") + a horror sound pass.** `client/DreadClient.java` is
  a client-only director that runs during NORMAL play (stands down during the
  apocalypse via new `ApocalypseClient.isActive()`, and off when
  `Config.ENABLE_DREAD` is false). An "unease" meter rises with dark / night /
  underground / alone / a mod-entity-standing-behind-you and drives, on long
  unpredictable cooldowns: a breathing vignette, a quickening heartbeat, whispers
  placed *behind* the camera, a subliminal single-frame face flash, paranoia
  chat lines, and a rare "lights out" beat. Cosmetic only. **Every sound file was
  also re-processed into a horror version** — pitched down, slowed, bit-crushed
  and drowned in reverb (heavy for krave_*/deaths/hurts/alarm, gentler for the
  `va_*` dialogue + idles so they stay comical). Kept MONO so positional audio
  still works. The transform lives in `tools/make_horror.ps1` — **run it LAST
  after any `make_*.ps1` regen or the clean audio comes back.** Processed here
  with ffmpeg 8; not yet built with Gradle or heard in-game.
- **Quest system rebuilt as a branching graph (`quest/Quests.java`).** The old
  design was a single `QuestStage` int marching 0→10 in one straight line. It is
  now a directed graph: a hub (`START`) fans into six directions — **Story,
  Grass, Krave, Cayden, Fame, Streets** — worked in any order, re-converging on a
  `PEACE` finale. Two completion types: **collect** quests auto-complete when
  every listed item is in inventory (checked in `EventHandler.onPlayerTick` →
  `Quests.tick`), and **event** quests fire from the canon hooks (Barbara
  recruit, Krave summon/slay, red-hat dance, mouse smash, $500 deal, sewer,
  revenge). The collect quests between them name **every item in the mod**, so
  finishing the questline literally means collecting one of everything; `PEACE`
  is gated on all of them. Progress moved from an int to a string-list of done
  ids on the Quest Book NBT (`KraveDone`), plus a `KraveSeen` set so unlock
  notices never repeat. `QuestBookScreen` is now a two-column branch board with
  done/available/locked markers. **Compiles cleanly against the source; not yet
  built with Gradle or run in-game** (no `.tools/` on this Linux box).
- **Red overlay removed entirely.** The user was emphatic: *"there shouldn't
  even really be an overlay. the sky should turn blood red."* The fullscreen
  fill is gone. `ApocalypseClient.renderBloodSky()` draws a real red shell at
  `RenderLevelStageEvent.Stage.AFTER_SKY` with `depthMask(false)` — before
  terrain, so the world paints over it and nothing is obscured. Fog tint capped
  at 0.45 with a floor on green/blue so it can never go black.
- **30 s post-respawn immunity** for Cayden and Barbara (`GRACE_TICKS = 600`).
  Critically, `fallDistance` is zeroed every tick during the window — otherwise
  they bank a lethal fall while immune and die the instant it expires, which is
  the exact loop the user reported.
- **The Krave Manual** (`krave_manual`) — an in-game book, granted on first
  join, 9 chapters opening on Rule #1. `KraveManualScreen`. The user explicitly
  wanted this in-game, not as a web page.

## Working style this user expects

- They report bugs bluntly and in batches (*"alright its completely bad"*).
  Take the whole list seriously; they are usually describing real defects.
- They want maximalism — *"be way way way more creative"*, *"a minimum of 100
  pieces of content"*, *"everything should be custom"*. Do not scale down.
- **Verify generated files exist on disk afterwards.** A PowerShell helper named
  `Sv` once silently resolved to `Set-Variable` and 37 icon files were never
  written; the user found out as missing-texture checkerboards. Watch for alias
  collisions (`R`, `NI`, `Sv`). Write files with
  `[System.IO.File]::WriteAllText(..., new UTF8Encoding($false))` — a BOM from
  `Set-Content -Encoding utf8` once broke `build.gradle`.
- Check uncertain APIs against the decompiled jar with `javap` instead of
  guessing.
- `mods.toml` must use Forge's `mandatory=true`, **not** NeoForge's
  `type="required"`.
